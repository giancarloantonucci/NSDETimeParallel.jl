NSDETimeParallel.AbstractPararealBackend — Type
AbstractPararealBackend

How the fine sweep of Parareal executes. The algorithm lives ONCE in parareal/parareal.jl; a backend supplies only these primitives:

  • is_root(backend) — whether this process runs the serial parts (coarse init, correction, convergence check). true everywhere except non-root MPI ranks.
  • sync_starts!(backend, cache, k) — make the chunk starting values U[n] available wherever chunk n will be solved. No-op off MPI.
  • fine_map!(backend, cache, solution, problem, parareal, k; …) — solve chunks k:N with the fine solver; deposit boundary values into cache.F[n+1] on the root and chunk solutions into solution.lastiterate (MPI ranks keep their chunk local until collect_chunks!).
  • snapshot!(backend, solution, k; …) — record iterate k when saveiterates is on. In memory by default; on MPI the ranks have already written their chunk to the run directory inside fine_map!.
  • sync_converged(backend, flag) — agree the convergence decision.
  • collect_chunks!(backend, solution, cache; …) — bring final chunks (and, under MPI with saveiterates, the per-iterate history) to the root.

NSDETimeParallel.PararealCache — Type
PararealCache <: AbstractTimeParallelCache

Pre-allocated state for one Parareal run: the chunk boundary values U, the fine and coarse boundary results F and G, the previous-iterate snapshot U_ for the error function, the chunk time grid T, the chunk problems (built once, their u0 slots referencing U so the correction updates them in place), and reusable solver caches. Method-dependent fields can be replaced when switching solver, RHS, or weight-rule types; the state shape and chunk count stay fixed. Each run refreshes the initial state from the supplied problem. Moving a cache to a different span requires shiftwindow!. RHS changes rebuild the chunk caches; do not mutate RHS internals in place while retaining their solver caches.

NSDETimeParallel.PararealIterate — Type
PararealIterate <: AbstractTimeParallelIterate

A composite type for a single iterate in a PararealSolution: one fine chunk solution per time chunk. The chunk storage is CONCRETE — chunks are built eagerly from the fine solver, so eltype(iterate.chunks) is the fine solver's concrete solution type, not an abstract box. This matters: these objects cross thread and process boundaries in the hot path.

NSDETimeParallel.PipelinedMPIBackend — Type
PipelinedMPIBackend()

MPI frontier scheduling with one rank per chunk. Supported criteria are WeightedDefect(p=Inf, weight=FixedWeight(...)), FrontierRelativeUpdate, and NoStop. Other criteria are rejected; the bulk all-interface update rule and changing secant weights require synchronized iterates.

Maximum-defect acceptance waits for the upstream start to freeze before accepting its outgoing defect. Thus the assembled accepted starts satisfy the selected defect tolerance. Converting that tolerance to a trajectory error additionally requires bounds on the fine-map amplification.

Call MPI.Init() first and launch at least N ranks. Global histories are unsupported. Diagnostics report actual total fine/coarse calls and per-chunk local_sweeps; sweeps and fine_batches are nothing because this schedule has no synchronized batches. residuals contains the maximum diagnostic among ranks active at each local iteration index, not a bulk residual.

The final gather returns each fine trajectory from its accepted start. With NoStop() and K >= N, completion reproduces reference(problem, solver).

NSDETimeParallel.Wnorm — Method
Wnorm(iterate, reference, weight; base=:time)

Weighted Euclidean distance at the chunk interfaces. reference may be a solution or the vector returned by reference(problem, parareal). The base is per unit time, matching all weight rules. base=:chunk explicitly selects the per-chunk convention. Supply a scalar or FixedWeight; adaptive rule objects contain only their initial settings and are refused. To use a measured weight, pass solution.diagnostics.weights[end], or call Wnorm(solution, reference).

NSDETimeParallel.contractionrate — Method
contractionrate(errors::AbstractVector{<:Real}) :: Float64
contractionrate(solution::AbstractTimeParallelSolution) :: Float64

the observed per-iteration contraction rate β of an error trace: the least-squares slope of log(errors[k]) against k, exponentiated, so that errors[k] ≈ C βᵏ. Non-finite entries and EXACT ZEROS are excluded before fitting — finite termination drives the last error to bitwise zero, which is a property of the algorithm's fixed point, not of its rate. Returns NaN when fewer than two usable points remain: a run that converges in one iteration exhibits no observable rate, and downstream bounds (e.g. the outer radius R = r/βᴷ) must treat that as unbounded rather than fabricate a number.

NSDETimeParallel.correct! — Method
correct!(cache, parareal, k; mpi=false)

the serial Parareal correction sweep after fine batch k: re-run the coarse solver from the freshest starts and update U[n+1] = F[n+1] + (Gnew − Gold), writing in place against the U_ snapshot maintained by the iteration loop.

Two details make finite termination exact in floating point, not just in real arithmetic:

  • Order of operations. F + (Gnew − Gold) returns F bitwise whenever the two coarse values cancel bitwise; (Gnew + F) − Gold does not — it rounds F into Gnew first and loses low bits (with Gnew = Gold = 1e16 and F = 1 it returns 0). Do not "simplify" this expression.
  • The newly exact interface is assigned, not computed. After batch k the start U[k] is already exact, so F[k+1] is the exact value of U[k+1] and U[k] has not moved since G[k+1] was last computed: the coarse re-run at n = k would reproduce G[k+1] bitwise. Skip it and copy F[k+1] across — one coarse solve saved per sweep, and no arithmetic on the exact prefix at all.

NSDETimeParallel.costratio — Method
costratio(problem, parareal; repeats=3) :: Real

measures ζ, the coarse/fine cost ratio over ONE chunk of problem under parareal's chunking — the input theoretical_speedup needs. Both solvers are timed on the first chunk with @elapsed (best of repeats, after a compile warm-up). NSDETimeParallel.flatten — Method
flatten(iterate::PararealIterate)

concatenates the chunk solutions into one pair of vectors (u, t), dropping each chunk's FIRST point after chunk 1: boundaries are stored twice (chunk n's last point and chunk n+1's corrected start), and keeping both would double-weight every boundary in any downstream statistic. The kept value is the fine endpoint; the dropped corrected start agrees with it only to the solve tolerance. t is monotone.

NSDETimeParallel.iteration_budget — Method
iteration_budget(S::Real, N::Integer, ζ::Real; estimate=:wallclock) :: Int

returns the largest fine-batch budget K ∈ 1:N that reaches the target modelled speed-up S; returns zero if none does. A returned K permits K-1 corrections. This is a cost budget, not a prediction that the iteration converges within that budget.

NSDETimeParallel.seams — Method
seams(iterate::PararealIterate) :: Vector{<:Real}

returns the N − 1 chunk-boundary seam sizes of iterate: at each interior boundary, ‖(start of chunk n+1) − (end of chunk n)‖ — the distance between the corrected starting value U[n+1] and the fine endpoint F(U[n]) it should agree with at convergence. This is exactly the discontinuity that flatten hides by dropping the corrected start, so any statistical claim made on flattened output should report maxseam alongside it: under the weighted criterion ψ₂, late-window seams are unconstrained BY DESIGN (the discount forgives them), and only the seam sizes say which regime a run actually exercised. Empty for a single-chunk iterate.

NSDETimeParallel.shiftwindow! — Method
shiftwindow!(cache::PararealCache, τ0, τN)

re-targets a cache at the window [τ0, τN]: recomputes the chunk grid T and updates every chunk problem's tspan in place. This is the official seam for window drivers (e.g. NSDEMovingWindow) — chunk problems are built once at cache construction, so their time spans must be moved through this function, never by poking cache.T alone.

NSDETimeParallel.theoretical_speedup — Method
theoretical_speedup(K::Integer, N::Integer, ζ::Real; estimate=:wallclock) :: Real
theoretical_speedup(diagnostics::PararealDiagnostics, ζ::Real; estimate=:wallclock) :: Real
theoretical_speedup(solution::PararealSolution, ζ::Real; estimate=:wallclock) :: Real

returns the modelled speed-up over N serial fine chunks. K is the number of fine batches, not corrections: a finite bulk return has s = K-1, with 1 ≤ K ≤ N. The cost ratio ζ is coarse/fine time per chunk; see costratio.

The exact-prefix implementation uses K_G = K*(N-1) - K*(K-1)/2 coarse calls and K*N - K*(K-1)/2 fine calls, including the initial coarse pass and final fine batch. The diagnostics overload uses the recorded call counts directly.

  • :wallclock (default) charges one fine-chunk time per batch and sequential coarse calls: N/(K + ζ*K_G). It assumes at least N workers and equal chunk costs, and excludes communication, synchronization, and load imbalance.
  • :work divides the total fine-call cost by N, retaining the same sequential coarse cost. This assumes perfect redistribution of the shrinking fine work; it is not the critical path of the bulk backend.

These are cost models, not measured speed-ups or unconditional performance bounds. The compatibility keyword wallclock=false selects :work, while an explicit estimate takes precedence. Pipeline diagnostics, nonfinite or unstarted runs, and runs with no fine batch are refused: a pipeline needs its task schedule.
